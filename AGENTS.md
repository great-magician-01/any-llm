# AGENTS.md

## Architecture

- **Monorepo**: Go backend (root, module `github.com/great-magician-01/any-llm`) + Vue 3 SPA frontend (`web/`)
- **Backend**: single-binary Go app with embedded frontend via `//go:embed web/dist` (relative to `cmd/any-llm/`)
- **Frontend**: Vue 3 + Naive UI + Vue Router (hash history) + Axios, built with Vite. Two parallel page sets: classic dark theme (`web/src/views/`, routes `/login`, `/dashboard`, ...) and a glassmorphism set (`web/src/glass/`, same pages under the `/glass` route prefix, e.g. `/glass/dashboard`) — glass views reuse `web/src/api`, `web/src/utils` and shared components (`StatCard`, `BarChart`, ...), adapting via CSS-var overrides in `web/src/glass/glass.css` + a nested `n-config-provider` in `web/src/glass/GlassShell.vue`; `body.glass-mode` (toggled by the router) styles teleported popups. Both sets support light/dark: `web/src/composables/useTheme.ts` resolves the mode (localStorage `any-llm-theme` > `prefers-color-scheme` > dark) onto `<html data-theme>`, an inline script in `web/index.html` presets it before first paint, and each set ships two `GlobalThemeOverrides` (`web/src/theme.ts`, `web/src/glass/theme.ts` — surfaces/text/borders only, brand colors shared) plus a `:root[data-theme='light']` CSS-var block per stylesheet; `web/src/components/ThemeToggle.vue` is the entry point (both sidebars + both login pages)
- **DB**: SQLite (`modernc.org/sqlite`), PostgreSQL (`jackc/pgx/v5`) or MySQL 8.0.13+ (`go-sql-driver/mysql`) — all pure Go, no CGO. Selected via `DB_TYPE`; tables auto-created on startup via `db.OpenSQLite` / `db.OpenPG` / `db.OpenMySQL`. Schema is defined **once** in `internal/db/schema.go` and rendered per dialect — see the Gotchas entry on dialect abstraction
- **No frameworks** on backend: stdlib `net/http` only
- **Translation layer**: requests flow through an IR (`internal/translate/`) — OpenAI/Anthropic in/out, any upstream format
- **9 internal packages**: `auth`, `config`, `db`, `gateway`, `logger`, `model`, `translate`, `upstream`, `webapi`

## Git workflow

- **Documentation-only changes** (`CLAUDE.md`, `AGENTS.md`, `readme.md`, `docs/**`) are committed **directly on `master`** — no branch, no PR needed.
- **Anything that changes code** (`bugfix` / `feat` / `refactor`, i.e. any `.go`, `web/`, migration, Dockerfile, or CI change, tests included) must be done on a **new branch** — never commit it straight to `master`.
- Branch names follow `<type>/<slug>` (see recent history: `fix/log-daily-rotation`, `feat/upstream-concurrency-limit`), then merged back to `master` by PR.

## Build & Run

```bash
# Full build (frontend must be built first — it auto-copies dist into cmd/any-llm/web/dist/ for embedding)
cd web && npm run build && cd ..
go build -o any-llm.exe ./cmd/any-llm/

# Docker build (multi-stage: node->golang->alpine)
docker build -t any-llm .

# Dev (two terminals)
go run ./cmd/any-llm/                    # terminal 1: backend on :6718 (default)
cd web && npm run dev                    # terminal 2: Vite HMR, proxies to :6718
```

`npm run build` runs `vue-tsc -b && vite build && <copy dist to ../cmd/any-llm/web/dist>`.

## Testing

```bash
go test ./...                            # all Go tests
go test ./internal/gateway -v            # single package with verbose
```

- Backend tests use stdlib `testing`, in-memory SQLite via `t.TempDir()`
- **DB e2e suites** are gated on env DSNs and skip when unset: `DB_TEST_PG_DSN` (PostgreSQL, `internal/db/pg_e2e_test.go` + `internal/gateway/pg_conv_e2e_test.go`) and `DB_TEST_MYSQL_DSN` (MySQL, `internal/db/mysql_e2e_test.go`). Both create a uniquely-named schema/database per test and drop it on cleanup, so they need create/drop privileges. `internal/db/mysql_e2e_test.go` is where the MySQL-specific semantics live (partial-unique-index lowering, `LastInsertId` in place of `RETURNING`, `ON DUPLICATE KEY UPDATE`, `DATE_FORMAT` day buckets, the `id_sequences` counter table) — if you change any of those, that file is the regression net
- Frontend tests: vitest + happy-dom (`cd web && npm run test`), covering the router auth guard, the axios 401 interceptor and the theme composable
- **CI**: `.github/workflows/ci.yml` runs gofmt check, `go vet`, `go test`, `go build` (with a stub `cmd/any-llm/web/dist/`), plus `npm run test` and `npm run build`. The backend job runs a `mysql:8.0` service container and sets `DB_TEST_MYSQL_DSN`, so the MySQL e2e suite actually executes in CI
- No golangci-lint/staticcheck config — linting is gofmt + go vet only

## Logging

- `internal/logger` wraps stdlib `log/slog` (text handler), writing to **both** stdout and the configured log file (append mode, parent dirs auto-created)
- Log files rotate daily (local time): the file lives at `<dir>/<YYYY-MM-DD>/<name>.log`; `dailyFileWriter` checks the date on every write and opens the new day's file after midnight — no restart needed
- All HTTP requests logged via `gateway.LoggingMiddleware` (method, path, status, size, duration, remote)
- Gateway completion requests additionally log: key id/label, upstream, model, in_format, stream flag, token usage, status
- Upstream errors are logged with status code and truncated response body (≤512 chars)

## Routes

- `/v1/*` — public gateway (ext-key auth via `Authorization: Bearer all-sk-...`)
  - `GET /v1/models`, `POST /v1/chat/completions` (OpenAI), `POST /v1/messages` (Anthropic)
  - Model format in request body: `upstream-name/model-name`, **or a model alias** (fixed external name): the full model string is exact-matched against active aliases first (aliases take precedence, even names containing `/`); an alias resolves to an ordered binding list of `upstream + real model` that is tried in `priority` order with automatic failover (disabled, upstream-limit-exceeded, or concurrency-full candidates are skipped before dispatch; once stream events flow, no failover). Usage records store the **actual** upstream model per attempt.
  - Per-upstream **concurrency cap** (`max_concurrent`, admin create/update + config import/export; default 100, `0` = unlimited, negative rejected 400): the gateway enforces it with one in-memory semaphore per upstream id (`internal/gateway/concurrency.go`), acquired per candidate at dispatch — a stream holds its slot until the upstream stream ends, a non-stream call until the body is fully read. A full candidate is skipped for the next one (no usage record, no upstream call); when ALL candidates are full the client gets 429 `rate_limit_error` — cleanly before headers for streams (SDKs auto-retry), as the final error for non-streams. Limit changes take effect on the next request (the semaphore is rebuilt when the resolved row's value differs; in-flight requests on the old semaphore are never preempted, so a lowered limit can be transiently exceeded).
  - Per-key model allowlist: each ext key can be restricted to specific public model names — alias names or `upstream/model`, exactly the ids `/v1/models` lists (`allowed_models` on the key, admin `POST/PUT /api/admin/keys`; empty = unrestricted, exact match only, entries need not exist yet). A request for an unlisted model is rejected 403 `permission_error`; `/v1/models` itself requires an ext key and lists only that key's allowed models.
  - **Config read cache** (`internal/model/cache.go`): ext-key auth, the direct `name/model` upstream row and alias binding chains are served from a process-local read-through cache — the first request for a given key/upstream/alias hits the DB, later ones are pure memory (hits return copies, since the gateway shares the cache across goroutines). Token-limit checks and `/v1/models` still query the DB every time. Consistency is **write-time only**: every config write in `internal/model` (`Create`/`Update`/`Delete` for keys, upstreams and aliases) refreshes or evicts the affected entries immediately after the DB write succeeds, inside the same `writeSync` closure, so an admin change is visible on the next request — and because all admin CRUD plus config import funnel through those functions, there is no call site that can forget to invalidate. Consequences to know: cache misses (unknown key / unknown upstream name / a model string that is not an alias) are **not** cached, so they keep hitting the DB; alias candidates are stored unfiltered and expiry is evaluated per read against that request's `now`; `last_used_at` touches deliberately do not invalidate; and **out-of-band DB edits (raw SQL, or several processes sharing one database) are invisible until the process restarts** — there is no TTL and no env switch.
  - Upstreams can be **disabled** via admin (`PUT /api/admin/upstreams/:id` with `{"enabled": false}`; the same optional field on create pre-disables a new upstream) — a lighter alternative to delete: alias bindings skip disabled upstreams (failover kicks in, all-disabled aliases 404 "has no available bindings"), direct `name/model` requests get 404 "upstream 'x' is disabled", and `/v1/models` omits them. Unlike delete, models and alias bindings are preserved so re-enabling restores service.
  - Upstreams can be given an **expiry** (`expires_at`, nullable; admin create/update + config import/export, NULL = never expires) — after it passes the upstream stops serving on the next request: alias candidates drop out of the chain (failover to the next binding, all-expired aliases 404 "has no available bindings"), direct `name/model` gets 404 "upstream 'x' is expired", and `/v1/models` omits it. The check is a lazy read-time comparison (`model.Upstream.Expired`, one `time.Now()` per request) — no background job, no cache to invalidate. It is **independent of `enabled`**: expiry never writes the flag, so extending the date restores service without re-enabling. Balance polling/refresh also skip expired upstreams. Partial updates need three states, hence `webapi.optTime`: field absent keeps the current value, explicit `null` clears it (an upstream left enabled but past its date is the normal state, and the UI's switch-only PATCH must not wipe it).
- `/api/admin/*` — admin API (HMAC session auth, cookie `s`)
  - CRUD for upstreams, models, ext keys, model aliases (`/api/admin/aliases`); usage summary/records. Ext keys carry a display name in the `label` column (required by the UI) plus a free-form `remark`; labels are trimmed server-side and non-empty labels are unique among active keys — app-layer check returns 400 `key label already exists` (skipped when an update doesn't change the label, so legacy duplicate names don't lock the key), backed by partial unique index `idx_ext_keys_label` (boot logs a warning and skips it when legacy duplicates exist; dedupe manually and it self-creates on next start). `GET /api/admin/usage/summary?group_by=key` reports the joined key `label` as `group_key` — falling back to `#<id>` for an empty label or a missing key row, then `—` when the record has no key id — while still grouping by `ext_key_id` (emitted as `ext_key_id` in key-dimension rows so clients can tell same-labelled rows apart), so two same-labelled keys stay separate rows and a renamed or soft-deleted key shows its current name (no name snapshot in `usage_records`)
  - `GET /api/admin/balances` — latest vendor balance/quota snapshot per upstream; `POST /api/admin/balances` — live-fetch + archive all supported, enabled upstreams (page-open auto-refresh); `GET /api/admin/upstreams/:id/balances[?page=&size=]` — paginated snapshot history; `POST /api/admin/upstreams/:id/balances/refresh` — live fetch + archive (400 for unsupported vendors, 502 on vendor API failure). Snapshots live in `balance_snapshots`; a background poller (`internal/upstream/balance_poller.go`, interval `ANY_LLM_BALANCE_INTERVAL`, plus one run at boot when the interval is > 0) archives every supported, enabled upstream. Vendor is identified by base-URL host: `api.deepseek.com` → `GET /user/balance`, `api.kimi.com` → `GET /coding/v1/usages`; payloads are normalized JSON (`{"kind":"balance",...}` / `{"kind":"quota",...}`)
  - `GET /api/admin/conversations[?page=&size=]` and `/api/admin/conversations/:id` — read-only access to archived conversations (**PostgreSQL and MySQL**; SQLite does not archive at all, so there the list returns `{"data": [], "total": 0, "disabled": true}` and the frontend shows a hint). Responses never include the raw byte columns. Storage is **app-level monthly sharding** (`internal/model/conversation_shard.go`, design doc `docs/conversation-sharding.md`): writes route by `created_at` to `conversation_records_YYYY_MM` (auto-created via `model.EnsureConversationShard` on startup and on insert-miss); a pre-existing plain `conversation_records` table is kept untouched as the legacy shard. All shards share one id source so `id` stays globally unique — PG uses the sequence `conversation_records_id_seq`, MySQL uses the `id_sequences` counter table (`LAST_INSERT_ID(next_id + 1)`), which `db.NextShardID` abstracts; shard discovery goes through `db.ListTablesLike` (`pg_tables` on PG, `information_schema.TABLES` on MySQL) plus the Go-side name whitelist; a process-global registry cache (`model.LoadConvShards` at boot, refreshed on every shard creation) feeds reads — lists paginate shard-by-shard (newest month first, legacy last) via per-shard COUNT + window math, detail fans out `WHERE id=?` per shard
  - `GET /api/admin/config/export` — config backup: all upstreams (real API keys, models with lengths, enabled/limits) + model aliases with bindings addressed **by upstream name** (instance-stable); `POST /api/admin/config/import` — restore: same-name upstreams/aliases are overwritten (model list replaced exactly, bindings replaced), configs absent from the file are kept. `enabled`/token limits/`models` omitted from the file keep current values (base_url/api_key/format always follow the file); the whole file is validated before any write, duplicate names within a file are rejected 400; bindings referencing upstreams that exist neither in the file nor in the DB are dropped (`bindings_dropped` count; aliases left with none are skipped). Import is **not one transaction**: a mid-way DB failure leaves already-committed items in place — re-importing the same file is safe and converges (same-name overwrite is idempotent). Response `{"upstreams_created":…,"upstreams_updated":…,"aliases_created":…,"aliases_updated":…,"aliases_skipped":…,"bindings_dropped":…}`. Payload format `version` 1, `>1` rejected. UI lives on the Upstreams page (both classic and glass)
- `/*` — SPA fallback (serves embedded `web/dist/`; falls back to `index.html` for client-side routing)

## Gotchas

- **Graceful shutdown**: `main.go` uses `signal.NotifyContext` + `http.Server.Shutdown` (30s drain, then force-close). Deferred cleanup runs LIFO: `poller.Stop` (stops balance snapshot polling) → `writer.Stop` (drains queued usage writes) → `db.Close` → `logger.Close`. Server sets `ReadHeaderTimeout` (10s) but **no WriteTimeout** — SSE streams are long-lived.
- **`cmd/any-llm/web/dist/` must exist** when compiling the Go binary (`//go:embed web/dist`) — `npm run build` copies it there; CI stubs it with an empty `index.html`
- **Ext key format**: `all-sk-` prefix + 32 base62 chars
- **Session auth**: HMAC-SHA256, expiry from `ANY_LLM_SESSION_TTL` (default 24h, `0` = never — signed as a year-9999 expiry so verification needs no special case); sliding renewal — `authenticate` re-issues the cookie with a fresh full TTL when less than half remains; secret persisted in `ANY_LLM_SESSION_SECRET_FILE` (default `./.session-secret`, gitignored) when env unset
- **DB writer**: `internal/db.Writer` serializes all writes through a single goroutine (buffered channel, capacity 512). `DoAsync` is fire-and-forget (silently drops on full buffer / after Stop); `DoSync` blocks for the result and returns `ErrWriterStopped` (mapped to HTTP 503) if the server is shutting down. `Stop` waits for in-flight sync calls to finish before draining and exiting, so concurrent shutdown cannot deadlock or orphan in-flight admin writes.
- **Dialect abstraction — one schema definition, three renderers** (`internal/db/schema.go`): the canonical schema lives in a single `[]Table` value; `Column`/`Index` describe type, nullability, defaults, and partial-unique-index predicates. Per-dialect renderers turn that into `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE ADD COLUMN`. **Adding a column means editing that one definition** — there is no second `CREATE TABLE` to keep in sync (the old `migrationSQLite` / `migrationPG` / `sqliteSoftDeleteSpecs` trio, and its "keep these in sync" warning, are gone). Type mapping: SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` + `DATETIME`, PG `BIGSERIAL` + `TIMESTAMP(0)`, MySQL `BIGINT AUTO_INCREMENT` + `DATETIME(0)` (never MySQL's `TIMESTAMP` — it stops at 2038). Queries are written with `?` and passed through `db.Rebind(d, q)`, which rewrites to `$N` for PG only (SQLite and MySQL both use `?` natively); string literals (`'...'`, with `''` escape) and SQL comments (`--`, `/* */`) are skipped so `?` inside them is preserved. `db.DialectOf` infers the dialect from the driver — never store it as global state.
- **MySQL specifics** (all handled inside `internal/db` — do not sprinkle dialect switches through business code):
  - **No partial indexes.** The whole "unique among active rows" scheme is lowered to a MySQL *generated column + plain unique key*: a column `GENERATED ALWAYS AS (IF(<predicate>, <col>, NULL)) STORED` plus `UNIQUE KEY`. MySQL permits multiple NULLs in a unique index, so soft-deleted rows stop occupying the uniqueness slot — exactly the PG partial-index semantics. Do **not** emulate it as a plain composite `(col, is_active)` unique key: `NULL != NULL` means active rows would *not* collide, defeating the constraint.
  - **Indexes are inlined in `CREATE TABLE`** — MySQL has no `CREATE INDEX IF NOT EXISTS`. A `Column` with `TypeText` and no `Len` that needs an index or a PK makes the renderer **fail loudly** (`validateMySQL`); fix it by giving the column a `Len` (it renders as `VARCHAR`). Columns that are neither indexed nor keyed stay MySQL `TEXT` (no arbitrary length ceiling).
  - **Expression defaults (needs 8.0.13+).** MySQL rejects a *literal* default on `BLOB`/`TEXT`/`GEOMETRY`/`JSON` columns with error 1101 (`DEFAULT ''`), but accepts the same default wrapped as an *expression* (`DEFAULT ('')`). `effectiveDefault` wraps rather than drops it, so an empty string / empty object means the same thing on all three dialects — dropping it instead made `INSERT INTO ext_keys (key, label) VALUES (...)` work on PG/SQLite and fail with 1364 on MySQL.
  - **No `RETURNING`** → `db.InsertReturningID` / `db.InsertReturningIDTx` strip the suffix and use `LastInsertId()`. **No `ON CONFLICT`** → `db.ConflictIgnoreSuffix` / `db.UpsertSuffix` emit `ON DUPLICATE KEY UPDATE`.
  - **`key` is a reserved word** — `ext_keys.key` must go through `db.QuoteIdent` (backticks on MySQL, bare elsewhere).
  - **Collation**: tables are created `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin` and the DSN sets the same, because MySQL's default `utf8mb4_0900_ai_ci` is case/accent-**insensitive**, which would silently change uniqueness and `=` semantics relative to PG/SQLite's byte-exact comparison. (`utf8mb4_bin` is PAD SPACE, so trailing spaces still compare equal — the one residual divergence.)
  - **`UPDATE ... WHERE id = (SELECT MIN(id) FROM <same table> ...)`** hits MySQL error 1093; wrap the subquery in a derived table (`SELECT id FROM (SELECT MIN(id) AS id FROM ...) AS cand`) — that form works on all three dialects.
  - **Migration statements are executed one at a time** (`migrateMain` walks a `[]string`): go-sql-driver cannot `Exec` a multi-statement script.
  - **No legacy MySQL databases exist**, so `migrateSoftDelete` is a deliberate no-op there — do not add defensive backfill for a database that cannot exist.
- **`extraCols` semantics**: it lists only columns *added after the initial schema*, because a same-named table missing an initial-schema column (e.g. `ext_keys.label`) was not built by this project — fail loudly at query time and fix such databases manually rather than silently adding empty shell columns. Each entry renders through the schema renderer, so there is no hand-written coldef string to keep dialect-valid. On SQLite, `migrateSoftDelete` rebuilds tables (to drop legacy `REFERENCES`/inline `UNIQUE`/`CHECK`) and refuses to proceed if the legacy table is missing any canonical column — it names the missing columns instead of silently dropping them until the next restart.
- **Timestamp convention**: always write Go `time.Time` values in server-local time (`time.Now()`), never SQL `CURRENT_TIMESTAMP` defaults or `.UTC()`. PG `TIMESTAMP(0)` columns store the bare local wall clock (pgx discards the zone on encode); `OpenPG` registers a custom `timestamp` codec (`internal/db/pgtime.go`) that relabels scanned values from UTC to `time.Local`, so JSON serializes with the local offset and frontends convert correctly. SQLite stores RFC3339 text with the local offset and round-trips correctly on its own. MySQL uses `DATETIME(0)` (no timezone at all) with DSN `parseTime=true&loc=Local`, so the driver writes and reads the local wall clock — the same convention, no codec needed.
- **MySQL `max_allowed_packet`**: `gateway/conversation.go` caps an archived `response_raw` at 64 MiB, and the MySQL driver's *client-side* default cap is exactly 64 MiB — so without `maxAllowedPacket=0` in the DSN (which makes the driver follow the server's `@@max_allowed_packet`) the largest legal archive would always fail, and only inside the async writer's log. `OpenMySQL` sets it and warns at startup when the server value is under 128 MiB. Keep `max_allowed_packet` >= 256M on production MySQL servers.
- **Streaming**: always injects `stream_options: {include_usage: true}` into OpenAI upstream requests
- **No rate limiting middleware and no CORS middleware** — the only traffic shaping is the per-upstream in-flight concurrency cap described above
