# AGENTS.md

## Architecture

- **Monorepo**: Go backend (root, module `github.com/great-magician-01/any-llm`) + Vue 3 SPA frontend (`web/`)
- **Backend**: single-binary Go app with embedded frontend via `//go:embed web/dist` (relative to `cmd/any-llm/`)
- **Frontend**: Vue 3 + Naive UI + Vue Router (hash history) + Axios, built with Vite. Two symmetric page sets under `web/src/themes/`: `classic/` (routes `/login`, `/dashboard`, ...) and `glass/` (same pages under `/glass` prefix) — glass reuses `web/src/api`, `web/src/utils` and the shared components in `web/src/components/` (only components used by both sets live there), adapting via `glass.css` CSS-var overrides + a nested `n-config-provider` in `GlassShell.vue`; `body.glass-mode` (router-toggled) styles teleported popups. Light/dark: `web/src/composables/useTheme.ts` resolves mode (localStorage `any-llm-theme` > `prefers-color-scheme` > dark) onto `<html data-theme>`, an inline script in `web/index.html` presets it before first paint; each set ships two `GlobalThemeOverrides` **builder functions** in its `theme.ts` (surfaces/text/borders built in; brand colors per accent), plus a `:root[data-theme='light']` CSS-var block; `web/src/components/ThemeToggle.vue` is the entry point. **Accent (配色) is a second, orthogonal theme dimension**: `web/src/utils/accents.ts` is the palette registry (`default` blue + EVA `eva-01` 初号机紫绿 / `eva-02` 明日香红橙 / `eva-00` 凌波丽蓝黄), persisted under localStorage `any-llm-accent` onto `<html data-accent>` (the same index.html inline script presets it, value list kept in sync), and consumed two ways — naive-ui: `accentNaiveOverrides()`/`accentMenu()` merged inside the theme.ts builders (default keeps each suite's built-in blue; EVA values are shared across both suites; eva-02 also overrides the **error family to pink** so danger states stay distinguishable from the red primary); CSS: `:root[data-accent=…]` brand-var blocks in `style.css` and `glass.css` (brand/gradient/bg-glow/selection/glass blobs/buttons — hex values mirrored from accents.ts, sync + WCAG contrast guarded by `accents.test.ts`; light-mode contrast needs the combined `:root[data-theme='light'][data-accent=…]` selectors). Accent always persists (no system preference to follow). `web/src/components/AccentPicker.vue` (mounted next to ThemeToggle in both layouts and both login pages) is the entry point. Chart `PALETTE` and StatCard icon tints are deliberately **fixed** data-viz colors; Usage 输入/输出 series, UsageCalendar top levels, BrandMark and all brand glows follow the accent via `var(--brand…)`. Imports use the `@/` alias for `web/src/` (`vite.config.ts` + `tsconfig.app.json`)
- **DB**: SQLite (`modernc.org/sqlite`), PostgreSQL (`jackc/pgx/v5`) or MySQL 8.0.13+ (`go-sql-driver/mysql`) — all pure Go, no CGO. Selected via `DB_TYPE`; tables auto-created on startup via `db.OpenSQLite` / `db.OpenPG` / `db.OpenMySQL`. Schema is defined **once** in `internal/db/schema.go` and rendered per dialect — see the Gotchas entry on dialect abstraction
- **No frameworks** on backend: stdlib `net/http` only
- **Translation layer**: requests flow through an IR (`internal/translate/`) — OpenAI/Anthropic in/out, any upstream format
- **9 internal packages**: `adminapi`, `auth`, `config`, `db`, `gateway`, `logger`, `store`, `translate`, `upstream`

## Git workflow

- **Documentation-only changes** (`CLAUDE.md`, `AGENTS.md`, `readme.md`, `docs/**`) are committed **directly on `master`** — no branch, no PR needed.
- **Anything that changes code** (`bugfix` / `feat` / `refactor`, i.e. any `.go`, `web/`, migration, Dockerfile, or CI change, tests included) must be done on a **new branch** — never commit it straight to `master`.
- Branch names follow `<type>/<slug>` (see recent history: `fix/log-daily-rotation`, `feat/upstream-concurrency-limit`), then merged back to `master` by PR.

## Build & Run

```bash
# Full build (frontend must be built first — it auto-copies dist into cmd/any-llm/web/dist/ for embedding)
cd web && npm run build && cd ..
go build -o any-llm.exe ./cmd/any-llm/

# Docker build (multi-stage: node->golang->alpine)
docker build -t any-llm .

# Dev (two terminals)
go run ./cmd/any-llm/                    # terminal 1: backend on :6718 (default)
cd web && npm run dev                    # terminal 2: Vite HMR, proxies to :6718
```

`npm run build` runs `vue-tsc -b && vite build && <copy dist to ../cmd/any-llm/web/dist>`.

## Testing

```bash
go test ./...                            # all Go tests
go test ./internal/gateway -v            # single package with verbose
```

- Backend tests use stdlib `testing`, in-memory SQLite via `t.TempDir()`
- **DB e2e suites** are gated on env DSNs and skip when unset: `DB_TEST_PG_DSN` (PostgreSQL, `internal/db/pg_e2e_test.go` + `internal/gateway/pg_conv_e2e_test.go`) and `DB_TEST_MYSQL_DSN` (MySQL, `internal/db/mysql_e2e_test.go`). Each creates a uniquely-named schema/database per test and drops it on cleanup, so they need create/drop privileges. `mysql_e2e_test.go` is the regression net for the MySQL-specific semantics (partial-unique-index lowering, `LastInsertId` for `RETURNING`, `ON DUPLICATE KEY UPDATE`, `DATE_FORMAT` day buckets, the `id_sequences` counter table)
- Frontend tests: vitest + happy-dom + `@vue/test-utils` (`cd web && npm run test`, `test:coverage`) — pure-function/composable tests plus **component tests** (the Upstreams page is the reference), a classic-vs-glass **theme parity** test (both sides must call the same composable and produce the same request sequence), the router guard matrix and the axios interceptor/contract. Shared helpers live in `web/src/test/` (excluded from coverage). Coverage is still modest (~28%) — add component tests the same way
- **CI**: `.github/workflows/ci.yml` runs gofmt check, `go vet`, `go test -cover`, `go build` (with a stub `cmd/any-llm/web/dist/`), plus `npm run test` and `npm run build`. The backend job runs `mysql:8.0` and `postgres:17` service containers with `DB_TEST_MYSQL_DSN` + `DB_TEST_PG_DSN` set, so both e2e suites execute in CI (no coverage threshold gate)
- No golangci-lint/staticcheck config — linting is gofmt + go vet only

## Logging

- `internal/logger` wraps stdlib `log/slog` (text handler), writing to **both** stdout and the configured log file (append mode, parent dirs auto-created)
- Log files rotate daily (local time): `<dir>/<YYYY-MM-DD>/<name>.log`; `dailyFileWriter` checks the date on every write and opens the new day's file after midnight — no restart needed
- All HTTP requests logged via `gateway.LoggingMiddleware` (method, path, status, size, duration, remote)
- Gateway completion requests additionally log: key id/label, upstream, model, in_format, stream flag, token usage, status
- Upstream errors are logged with status code and truncated response body (≤512 chars)

## Routes

- `/v1/*` — public gateway (ext-key auth via `Authorization: Bearer all-sk-...`)
  - `GET /v1/models`, `POST /v1/chat/completions` (OpenAI), `POST /v1/messages` (Anthropic)
  - Model format in request body: `upstream-name/model-name`, **or a model alias** (fixed external name): the full model string is exact-matched against active aliases first (aliases take precedence, even names containing `/`); an alias resolves to an ordered binding list of `upstream + real model` tried in `priority` order with automatic failover (disabled, upstream-limit-exceeded, concurrency-full, or failure-cooling candidates are skipped before dispatch; once stream events flow, no failover). Usage records store the **actual** upstream model per attempt.
  - Per-upstream **concurrency cap** (`max_concurrent`, admin create/update + config import/export; default 100, `0` = unlimited, negative rejected 400): one in-memory semaphore per upstream id (`internal/gateway/concurrency.go`), acquired per candidate at dispatch — a stream holds its slot until the upstream stream ends, a non-stream call until the body is fully read. A full candidate is skipped for the next one (no usage record, no upstream call); when ALL candidates are full the client gets 429 `rate_limit_error` — cleanly before headers for streams (SDKs auto-retry), as the final error for non-streams. Limit changes apply on the next request (the semaphore is rebuilt when the value differs; in-flight requests are never preempted, so a lowered limit can be transiently exceeded).
  - Per-candidate **failure cooldown** (`internal/gateway/failure_cache.go`, in-memory like the semaphores): a candidate call that fails with an upstream-side error — transport error, 5xx, 401/402/403 (dead key / no balance / banned), or 429 — marks the `(upstream, model)` pair for a fixed **60s** cooldown and is skipped at dispatch (no upstream call, no usage record), so a broken binding stops being hit on every request. Request-level 4xx (400/404/422…) never marks: one malformed request must not shut the chain down. Entries expire lazily — the first request after the TTL probes the candidate, success clears the entry, failure re-cools (a permanently broken upstream is hit at most once per 60s). When ALL candidates are cooling the client gets a clean 503 (`server_error`/`api_error` via `mapErrorType`; for streams decided in `acquireCandidate`, before headers flush) — mixed cooling + concurrency-full stays 429. Mid-stream failures and client disconnects never mark.
  - Per-key model allowlist: each ext key can be restricted to specific public model names — alias names or `upstream/model`, exactly the ids `/v1/models` lists (`allowed_models` on the key, admin `POST/PUT /api/admin/keys`; empty = unrestricted, exact match only, entries need not exist yet). A request for an unlisted model is rejected 403 `permission_error`; `/v1/models` itself requires an ext key and lists only that key's allowed models.
  - **Config read cache** (`internal/store/cache.go`): ext-key auth, the direct `name/model` upstream row and alias binding chains are served from a process-local read-through cache (hits return copies — the cache is shared across goroutines). Each entry carries a **fixed 1-hour TTL**: expiry = miss (re-query, re-store), and a failed re-query keeps the previous entry. Concurrent misses are **single-flighted** (one goroutine queries, the rest wait on the in-flight flight record; negative results included, so a burst of direct-route alias probes collapses to one query; the leader reports its DB error, waiters retry). The re-fill is **guarded twice**: it snapshots the pre-query entry plus a per-namespace write **generation counter** that every write-path function bumps (even no-op evictions and wholesale resets), and only stores if both are untouched — a config write landing mid-query can't be clobbered by a stale row. Token-limit checks and `/v1/models` still query the DB every time. Consistency is **write-time first**: every config write in `internal/store` (`Create`/`Update`/`Delete` for keys, upstreams, aliases) refreshes or evicts affected entries right after the DB write, inside the same `writeSync` closure — all admin CRUD plus config import funnel through these, so no call site can forget to invalidate; the TTL only bounds out-of-band edits (raw SQL, several processes on one DB). Cache misses (unknown key/upstream/alias) are **not** stored; alias candidates are stored unfiltered and `expires_at` is evaluated per read; `last_used_at` touches do not invalidate; no env switch.
  - Upstreams can carry **extra format endpoints** (`extra_endpoints`, JSON column of `[{"format","base_url"}]`; admin create/update + config import/export): at dispatch each candidate is resolved through `gateway.effectiveUpstream` — an extra endpoint whose `format` matches the inbound format is used as-is (**native passthrough, zero translation**), otherwise the primary `base_url`/`format` applies with IR translation. The *effective* format lands in `usage_records.up_format` / archives and drives the mid-stream error-type passthrough. `store.ValidateExtraEndpoints` (shared by admin CRUD and import) rejects an unknown format, empty `base_url`, duplicates, and any collision with the primary format — a PATCH changing the primary format into one colliding with a retained extra fails 400. `update` takes the field as a pointer (`nil` = keep, `[]` = clear — same three-state as `remark`); config import treats absent as keep, and export always emits it (`[]` when empty). Balance polling, `fetch-models` and the connectivity test use the primary endpoint only; the admin form tests each extra endpoint individually.
  - Upstreams can be **disabled** via admin (`PUT /api/admin/upstreams/:id` with `{"enabled": false}`; the same field on create pre-disables): alias bindings skip disabled upstreams (all-disabled aliases 404 "has no available bindings"), direct `name/model` gets 404 "is disabled", `/v1/models` omits them. Unlike delete, models and bindings are preserved so re-enabling restores service. `GET /api/admin/upstreams` takes `?status=enabled|disabled|all` (unknown values fall back to `all`); the default with no param is `all` because Dashboard/Keys/Aliases and config export rely on the unfiltered list — only the Upstreams page passes a status (defaulting to `enabled`).
  - Upstreams can be given an **expiry** (`expires_at`, nullable; admin create/update + config import/export, NULL = never): past it the upstream stops serving on the next request — alias candidates drop out (all-expired aliases 404), direct gets 404 "is expired", `/v1/models` omits it. Lazy read-time check (`store.Upstream.Expired`, one `time.Now()` per request) — no background job, no cache to invalidate. **Independent of `enabled`**: expiry never writes the flag, so extending the date restores service without re-enabling. Balance polling also skips expired upstreams. `adminapi.optTime` provides the three update states: field absent keeps the value, explicit `null` clears it.
- `/api/admin/*` — admin API (HMAC session auth, cookie `s`)
  - CRUD for upstreams, models, ext keys, model aliases (`/api/admin/aliases`); usage summary/records. Adding a model whose name is already active on that upstream returns **409** (`store.ErrModelExists`); editing a missing, soft-deleted, or cross-upstream model returns **404** (`UpdateModel` scopes by `upstream_id`). Upstream **names are unique among enabled upstreams only** — enforced at the app layer (`store.UpstreamNameTaken`; create/enable/rename that would collide return 400 `upstream name already exists`), with **no DB unique index**: the legacy partial index `idx_upstreams_name` is dropped at startup (`migrateDropLegacyUpstreamNameIndex`, incl. MySQL's generated-column + inline-unique-key lowering). Disabled and soft-deleted rows never occupy a name, so "prepare a same-named replacement while the old one still serves" works, and enabling a colliding row is rejected until the other one is disabled. Name lookups (`GetUpstreamByName` — gateway direct route and config-import matching) prefer the enabled row (`ORDER BY enabled DESC, id`), so a disabled duplicate never shadows the serving one; for the same reason the by-name read cache entry is evicted **by name** on every upstream write. Ext keys carry a display `label` (UI-required) plus a free-form `remark`; labels are trimmed server-side and non-empty labels are unique among active keys — app-layer 400 `key label already exists` (skipped when an update doesn't change the label), backed by partial unique index `idx_ext_keys_label` (boot warns and skips it when legacy duplicates exist; dedupe manually and it self-creates on next start). Upstreams carry an optional `remark` (display/config-export only, the gateway never reads it): create takes a plain string, **update must take a pointer** (`nil` = keep, `""` = clear) because the list page's enabled-switch PATCHes `{"enabled":…}` alone and a non-pointer field would wipe the remark on every toggle. Upstreams also carry a **tag** (`official` = 官方源站 default, `relay` = 中转站) with the same three-state update (`nil` = keep, `""` = reset to official, anything else 400 via `store.NormalizeTag` — also the write-boundary guard and read-side sanitizer, so a hand-edited row degrades to `official`). Like `remark` the gateway never reads it — no routing, failover, quota or `/v1/models` behavior depends on it. `GET /api/admin/usage/summary?group_by=key` reports the joined key `label` as `group_key` (falling back to `#<id>`, then `—` when the record has no key id) while still grouping by `ext_key_id` (emitted as `ext_key_id`), so same-labelled keys stay separate rows and a renamed or soft-deleted key shows its current name.
  - `GET /api/admin/balances` — latest balance/quota snapshot per upstream, filtered to upstreams that currently support balance fetch (an upstream repointed at an unsupported vendor — or at StepFun's `/step_plan` channel — stops showing its stale snapshots); `POST /api/admin/balances` — live-fetch + archive all supported, enabled upstreams (page-open auto-refresh); `GET /api/admin/upstreams/:id/balances[?page=&size=]` — paginated history; `POST /api/admin/upstreams/:id/balances/refresh` — live fetch + archive (400 unsupported vendor, 502 vendor API failure). Snapshots live in `balance_snapshots`; a background poller (`internal/upstream/balance_poller.go`, interval `ANY_LLM_BALANCE_INTERVAL`, plus one boot run when > 0) archives every supported, enabled upstream. Vendor by base-URL host: `api.deepseek.com` → `GET /user/balance`, `api.kimi.com` → `GET /coding/v1/usages`, `api.stepfun.com`/`api.stepfun.ai` → `GET /v1/accounts`; payloads normalized JSON (`{"kind":"balance"|"quota",...}`). StepFun base URLs whose first path segment is `step_plan` are **excluded**: that channel bills from a monthly Credit pool with no API-key-queryable endpoint, so showing the pay-as-you-go wallet there would be misleading.
  - `POST /api/admin/upstreams/test` and `POST /api/admin/upstreams/:id/test` — connectivity check (`internal/upstream/test.go`): a lightweight `GET {base}/models` with the format's auth headers (no chat call, no quota spent, 15s timeout). The first form tests an **unsaved** config (`base_url`/`api_key`/`format` in body); the second tests a saved upstream with optional same-name overrides (empty/masked `api_key` falls back to the stored key). Always 200 with `{"ok","reachable","latency_ms","status","models","detail"}`: `reachable=false` = transport error; `reachable=true` + `ok=false` = non-2xx (401/403 bad key, 404 no models listing); `ok=true` adds the model count. Offered in the add/edit form and per row (both themes).
  - `GET /api/admin/conversations[?page=&size=]` and `/api/admin/conversations/:id` — read-only archived conversations (**PostgreSQL and MySQL**; SQLite does not archive — the list returns `{"data": [], "total": 0, "disabled": true}` and the frontend shows a hint). Responses never include the raw byte columns. Storage is **app-level monthly sharding** (`internal/store/conversation_shard.go`, design doc `docs/conversation-sharding.md`): writes route by `created_at` to `conversation_records_YYYY_MM` (auto-created via `store.EnsureConversationShard` on startup and on insert-miss); a pre-existing plain `conversation_records` table is kept as the legacy shard. All shards share one id source — PG sequence `conversation_records_id_seq`, MySQL `id_sequences` counter table (`LAST_INSERT_ID(next_id + 1)`), abstracted by `db.NextShardID`; discovery via `db.ListTablesLike` plus a Go-side name whitelist; a process-global registry cache (`store.LoadConvShards` at boot, refreshed on shard creation) feeds reads — lists paginate shard-by-shard (newest month first, legacy last), detail fans out `WHERE id=?` per shard. The `harness` column is a **normalized client name** derived from the inbound `User-Agent` by `detectHarness` (`internal/gateway/harness.go`), an ordered specificity-first `{substr, canonical}` rule table — add a client by appending one entry: specific clients first (`claude-code`/`claude-cli`, `deepseek-harness`/`dsh/`, then `codex`, `aider`, `cursor`, `continue`, `windsurf`, `gemini-cli`), then generic SDK tokens (`openai` → `openai-sdk`, `anthropic` → `anthropic-sdk`) and transport defaults (`python-requests`, `go-http-client`, `curl`). When no rule matches, a **generic fallback** extracts the client name from the UA's first token shaped `name/version` (lowercased, letter-led `[a-z0-9._-]` name, digit version with optional `v` prefix — e.g. `ZCode/3.16.2 …` → `zcode`), anchored per whitespace-token and truncated to 64 chars (the MySQL VARCHAR(64) width); a UA with no such token (and an empty UA) is `unknown`. The verbatim UA always lands in `user_agent`.
  - `GET /api/admin/conv-sessions[?page=&size=]` and `/api/admin/conv-sessions/:id` — the **session-aggregated view** on top of per-request archiving (same PG/MySQL gating, same `disabled` convention). `conversation_sessions_YYYY_MM` shards share the `shardRegistry` machinery (instance `sessShards`; spec `docs/superpowers/specs/2026-10-07-conversation-sessions.md`): one row per conversation, upserted per turn — missing → insert into the current month's shard, found → update the row **in its first-turn month's shard** (cross-month continuation never moves rows). Each shard has `UNIQUE(session_id)`; cross-shard uniqueness relies on check-then-insert under the single-threaded `db.Writer`. A turn joins a session only when `extractConversationID` (`internal/gateway/convid.go`, ordered rule table) finds an id: `x-deepseek-harness-session-id` (`dsh:`), session-affinity headers `x-session-id`/`session_id`/`x-session-affinity` (`hdr:`), the Responses chain (`previous_response_id` resolved against the row's `last_response_id` inside the writer; root id = first turn's respID, `resp:` prefix), claude-code's `metadata.user_id` `session_<uuid>` suffix (`cc:`), or a generic `x-conversation-id` header. No id → not aggregated. Content is appended incrementally (`messages` JSON array, 16 MiB cap): stateless formats slice the delta off the resent history via `msg_count`, Responses turns carry their own delta, and compaction (`x-deepseek-harness-compact: 1` header or a shrunken history) inserts a `_marker` boundary message. Error turns only refresh `status`/`last_active_at` and **never advance `last_response_id`** (a retry with the previous `previous_response_id` lands back in the same row); a first turn that errors creates no row.
  - `GET /api/admin/config/export` — config backup: all upstreams (real API keys, models with lengths, enabled/limits) + aliases with bindings addressed **by upstream name**; `POST /api/admin/config/import` — restore: same-name upstreams/aliases are overwritten (model list replaced exactly, bindings replaced), configs absent from the file are kept. Fields omitted from the file keep current values (`base_url`/`api_key`/`format` always follow the file; export always emits `extra_endpoints` as `[]` when empty and always emits `tag` — absent means "keep" on import, and `tag: ""` resets to official; changing `format` while omitting `extra_endpoints` is rejected 400 when the retained extras would collide). The whole file is validated before any write; duplicate **alias** names rejected 400; duplicate **upstream** names are rejected unless the group matches the export round-trip shape (at most one enabled entry, every entry of the group setting `enabled` explicitly — export always does), in which case entries pair to same-name DB rows by enabled-state (enabled entry ↔ enabled row, disabled entries ↔ id-ascending disabled rows, surplus creates) so re-importing an export of a disabled-duplicate state converges; bindings referencing upstreams in neither file nor DB are dropped (`bindings_dropped` count; aliases left with none are skipped), and bindings to a name with multiple rows attach to the row `GetUpstreamByName` resolves (the serving one). Import is **not one transaction** — re-importing the same file is safe and converges (same-name overwrite is idempotent). Response `{"upstreams_created":…,"upstreams_updated":…,"aliases_created":…,"aliases_updated":…,"aliases_skipped":…,"bindings_dropped":…}`. Payload `version` 1, `>1` rejected. UI on the Upstreams page (both themes).
- `/*` — SPA fallback (serves embedded `web/dist/`; falls back to `index.html` for client-side routing)

## Gotchas

- **Graceful shutdown**: `main.go` uses `signal.NotifyContext` + `http.Server.Shutdown` (30s drain, then force-close). Deferred cleanup runs LIFO: `poller.Stop` → `writer.Stop` (drains queued usage writes) → `db.Close` → `logger.Close`. Server sets `ReadHeaderTimeout` (10s) but **no WriteTimeout** — SSE streams are long-lived.
- **`cmd/any-llm/web/dist/` must exist** when compiling the Go binary (`//go:embed web/dist`) — `npm run build` copies it there; CI stubs it with an empty `index.html`. The same applies to `go test ./...` locally, because `cmd/any-llm` has tests in the same package: without the stub the run fails with `pattern all:web/dist: no matching files found` (fix: `mkdir -p cmd/any-llm/web/dist && echo '<!doctype html>' > cmd/any-llm/web/dist/index.html`)
- **Ext key format**: `all-sk-` prefix + 32 base62 chars
- **Session auth**: HMAC-SHA256, expiry from `ANY_LLM_SESSION_TTL` (default 24h, `0` = never — signed as a year-9999 expiry so verification needs no special case); sliding renewal — `authenticate` re-issues the cookie with a fresh full TTL when less than half remains; secret persisted in `ANY_LLM_SESSION_SECRET_FILE` (gitignored) when env unset
- **DB writer**: `internal/db.Writer` serializes all writes through a single goroutine (buffered channel, capacity 512). `DoAsync` is fire-and-forget (silently drops on full buffer / after Stop); `DoSync` blocks for the result and returns `ErrWriterStopped` (HTTP 503) if the server is shutting down. `Stop` waits for in-flight sync calls before draining, so concurrent shutdown cannot deadlock or orphan admin writes.
- **Dialect abstraction — one schema definition, three renderers** (`internal/db/schema.go`): the canonical schema lives in a single `[]Table` value; `Column`/`Index` describe type, nullability, defaults, partial-unique predicates; per-dialect renderers emit `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE ADD COLUMN`. **Adding a column means editing that one definition** — no second `CREATE TABLE` to keep in sync. Type mapping: SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` + `DATETIME`, PG `BIGSERIAL` + `TIMESTAMP(0)`, MySQL `BIGINT AUTO_INCREMENT` + `DATETIME(0)` (never MySQL `TIMESTAMP` — it stops at 2038). Queries are written with `?` and passed through `db.Rebind(d, q)`, which rewrites to `$N` for PG only; string literals and comments are skipped so `?` inside them is preserved. `db.DialectOf` infers the dialect from the driver — never store it as global state.
- **MySQL specifics** (all inside `internal/db` — do not sprinkle dialect switches through business code):
  - **No partial indexes.** "Unique among active rows" is lowered to a *generated column + plain unique key*: `GENERATED ALWAYS AS (IF(<predicate>, <col>, NULL)) STORED` plus `UNIQUE KEY` (multiple NULLs allowed, so soft-deleted rows leave the uniqueness slot — PG partial-index semantics). Do **not** use a composite `(col, is_active)` unique key: `NULL != NULL` means active rows would not collide.
  - **Indexes are inlined in `CREATE TABLE`** — MySQL has no `CREATE INDEX IF NOT EXISTS`. A `TypeText` column with no `Len` that needs an index or PK makes the renderer **fail loudly** (`validateMySQL`); give it a `Len` (renders as `VARCHAR`). Unindexed columns stay `TEXT`.
  - **Expression defaults (needs 8.0.13+).** MySQL rejects a literal default on `TEXT`/`JSON` columns (error 1101) but accepts an expression default — `effectiveDefault` wraps (`DEFAULT ('')`) rather than dropping it, so an empty string/object means the same on all three dialects (dropping made `INSERT INTO ext_keys (key, label)` fail with 1364 on MySQL).
  - **No `RETURNING`** → `db.InsertReturningID[Tx]` strip the suffix and use `LastInsertId()`. **No `ON CONFLICT`** → `db.ConflictIgnoreSuffix` / `db.UpsertSuffix` emit `ON DUPLICATE KEY UPDATE`.
  - **`key` is a reserved word** — `ext_keys.key` must go through `db.QuoteIdent`.
  - **Collation**: tables are created `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin` (DSN sets the same), because MySQL's default `utf8mb4_0900_ai_ci` is case/accent-insensitive and would change uniqueness and `=` semantics vs PG/SQLite's byte-exact comparison. (`utf8mb4_bin` is PAD SPACE, so trailing spaces still compare equal — the one residual divergence.)
  - **`UPDATE ... WHERE id = (SELECT MIN(id) FROM <same table> ...)`** hits error 1093; wrap the subquery in a derived table — works on all three dialects.
  - **Migration statements run one at a time** (`migrateMain` walks a `[]string`): go-sql-driver cannot `Exec` a multi-statement script.
  - **No legacy MySQL databases exist**, so `migrateSoftDelete` is a deliberate no-op there — no defensive backfill for a database that cannot exist.
- **Post-initial columns** are flagged `LateAdd: true` on the `Column` declaration in `internal/db/schema.go` — the only registry; `migrateExtraCols` renders the `ALTER TABLE ADD COLUMN` from the same definition. Only columns added *after* the initial schema get the flag: a same-named table missing an initial-schema column was not built by this project — fail loudly rather than silently adding empty shells. Declared indexes are always created too (partial-unique via `migratePartialUniqueIndexes`, plain via `migratePlainIndexes`, MySQL inlined), and a test asserts a fresh DB holds every declared index and column. On SQLite, `migrateSoftDelete` rebuilds tables (dropping legacy `REFERENCES`/inline `UNIQUE`/`CHECK`) and refuses to proceed if the legacy table lacks a canonical column.
- **Timestamp convention**: always write Go `time.Time` in server-local time (`time.Now()`), never SQL `CURRENT_TIMESTAMP` defaults or `.UTC()`. PG `TIMESTAMP(0)` stores the bare local wall clock (pgx discards the zone on encode); `OpenPG` registers a custom `timestamp` codec (`internal/db/pgtime.go`) relabeling scanned values from UTC to `time.Local`, so JSON carries the local offset. SQLite stores RFC3339 text with offset. MySQL uses `DATETIME(0)` with DSN `parseTime=true&loc=Local` — same convention, no codec.
- **MySQL `max_allowed_packet`**: `gateway/conversation.go` caps an archived `response_raw` at 64 MiB, exactly the MySQL driver's client-side default cap — without `maxAllowedPacket=0` in the DSN (driver then follows the server's `@@max_allowed_packet`) the largest legal archive would always fail, only visible in the async writer's log. `OpenMySQL` sets it and warns when the server value is under 128 MiB. Keep `max_allowed_packet` >= 256M on production servers.
- **Streaming**: always injects `stream_options: {include_usage: true}` into OpenAI upstream requests
- **No rate limiting middleware and no CORS middleware** — the only traffic shaping is the per-upstream concurrency cap described above
